# Bagu V0.1 设计规格

## 1. 产品目标

Bagu 是一个面向大模型/NLP 校招算法岗的每日八股训练 App。V0.1 用一个完整的 Transformer 学习世界验证核心价值：用户是否愿意每天用 10～15 分钟，通过主动回答、结构化反馈、关键词解释和间隔复习，把零散知识练成可在面试中表达的答案。

V0.1 首先服务开发者本人，暂不追求付费、社区或增长指标。成功标准是能够连续使用 7 天，并形成完整的学习、反馈、复习闭环。

## 2. 目标平台与技术选型

- 客户端：Expo + React Native + TypeScript
- 路由：Expo Router
- 首批运行环境：Expo Go、Android、iOS 和 Web 预览
- 内容来源：项目内置的类型化本地数据
- 学习进度：本地持久化，不依赖账号和后端
- 状态管理：小型集中式学习状态，避免在 V0.1 引入复杂服务层
- 网络要求：核心学习流程完全离线可用

选择 Expo 是因为它能用一套代码快速验证 Android、iOS 与 Web。后续若需要原生能力，可继续生成原生工程或逐步迁移，不影响 V0.1 的内容模型。

## 3. 视觉方向

采用已确认的“明亮游戏化”方向：

- 紫色作为主操作色
- 黄色表示当前关卡
- 青绿色表示完成、正确和正反馈
- 浅灰紫表示未解锁或次要信息
- 大圆角、明确的层级、底部主按钮
- 纵向曲线路径组织课程节点
- 使用原创品牌和图形，不复制 Duolingo 商标、角色、文案或专有素材

交互节奏借鉴游戏化学习产品：短课程、即时反馈、经验值、连续学习、关卡解锁和清晰的下一步行动。

## 4. V0.1 内容范围

V0.1 只实现 Transformer 世界，共 20 个知识节点：

1. Attention 整体公式
2. Q、K、V 的含义
3. 缩放点积
4. Self-Attention
5. Cross-Attention
6. Multi-Head Attention
7. Padding Mask
8. Causal Mask
9. Attention 复杂度
10. FFN
11. 残差连接
12. LayerNorm
13. Pre-Norm 与 Post-Norm
14. 正弦位置编码
15. RoPE
16. Encoder 与 Decoder
17. BERT 与 GPT
18. KV Cache
19. MQA 与 GQA
20. FlashAttention

内容数量目标：

- 20 个知识节点
- 40～50 道基础题
- 15～20 道一级追问
- 5 道代码阅读或填空题
- 30 秒答案、详细解释、常见误区和关键词卡片

## 5. 核心页面

### 5.1 首页学习路径

首页显示：

- 连续学习天数、经验值、专注值
- 当前学习单元
- 纵向关卡路径
- 已完成、当前、锁定三种节点状态
- 点击当前节点开始课程
- 底部导航：首页、知识库、复习、个人

V0.1 中只有首页和复习页需要完整可用；知识库和个人页提供最小信息展示。

### 5.2 课程介绍页

用户点击当前节点后看到：

- 知识点名称
- 预计用时
- 本节学习目标
- 包含的题目数量
- 开始课程按钮

### 5.3 课程播放器

一节课程由 3～6 个步骤组成。支持以下题型：

- 单选题
- 多选要点题
- 关键词填空题
- 简短自由回答
- 代码阅读或填空题

顶部显示退出、课程进度和专注值；底部固定显示主操作按钮。

### 5.4 回答反馈

用户提交后不立即切换页面，而是在当前页面底部展示反馈区域：

- 正确或需要补充
- 已覆盖要点
- 缺失要点
- 常见错误提示
- 获得经验值
- 继续追问按钮

V0.1 的自由回答评估使用确定性的关键词与要点规则。AI 语义评分留到后续版本，避免首版依赖网络和产生不可控反馈。

### 5.5 关键词解释弹窗

答案中的预标记关键词可以点击。点击后从底部弹出解释卡片：

- 一句话定义
- 直觉解释
- 一个核心公式或示例
- 与当前问题的关系
- 返回题目按钮

每段答案最多标记 2～4 个关键词。弹窗关闭后保留原题位置和答题状态。

### 5.6 每日复习页

复习页显示：

- 今日待复习数量
- 薄弱知识点
- 开始复习按钮
- 本周复习完成情况

复习使用与课程相同的播放器，不重复实现另一套答题界面。

### 5.7 学习完成页

课程完成后显示：

- 本节获得经验值
- 正确率
- 新掌握知识点
- 需要复习的要点
- 返回路径按钮

## 6. 核心组件边界

### CoursePath

接收课程节点和学习状态，负责绘制纵向路径。它不直接修改进度，只发出节点选择事件。

### LessonPlayer

负责显示当前课程步骤、接收答案、切换反馈状态并推进题目。题型通过统一的数据结构渲染。

### AnswerFeedback

接收评估结果，显示覆盖要点、缺失要点和奖励。它不自行计算答案正确性。

### KeywordSheet

接收关键词详情并显示底部弹窗。它不访问课程状态，关闭后由父级恢复当前内容。

### ReviewQueue

根据学习记录和固定复习规则生成今日复习题。课程学习和复习共用 LessonPlayer。

### ProgressStore

统一保存节点状态、答题历史、经验值、连续学习和下次复习日期。所有持久化都通过该边界完成。

## 7. 数据模型

课程内容与用户进度分离。

### 静态内容

- World：学习世界
- Unit：专题单元
- KnowledgeNode：知识节点
- Lesson：一节课程
- Exercise：题目与题型
- Keyword：关键词解释
- Rubric：标准要点、常见错误和评分规则

### 用户进度

- NodeProgress：节点解锁、完成和掌握状态
- ExerciseAttempt：答案、结果和时间
- ReviewSchedule：下次复习时间和连续正确次数
- LearnerStats：经验值、连续学习和专注值

静态内容使用稳定 ID 与进度关联，内容文字调整时不破坏用户记录。

## 8. 数据流

```text
本地课程内容
    ↓
首页路径选择知识节点
    ↓
LessonPlayer 加载课程步骤
    ↓
用户提交答案
    ↓
评估规则生成 AnswerResult
    ↓
AnswerFeedback 展示反馈
    ↓
ProgressStore 保存答题和掌握状态
    ↓
ReviewQueue 更新下次复习日期
    ↓
首页和复习页重新读取进度
```

关键词弹窗只读取静态 Keyword 数据，不改变答题状态；用户主动加入复习时才更新 ReviewSchedule。

## 9. 复习规则

V0.1 使用简单、可预测的固定规则：

- 首次学完：第二天复习
- 第一次复习正确：3 天后
- 第二次连续正确：7 天后
- 三次及以上连续正确：14 天后
- 回答错误或选择“完全不会”：第二天再次出现

所有日期按用户设备本地日期计算。跨时区或云端同步不在 V0.1 范围内。

## 10. 错误和边界处理

- 本地进度损坏：保留静态内容，提示用户重置学习进度
- 内容引用缺失：跳过无效题目并记录开发日志，不阻断整节课程
- 用户中途退出：保存当前课程位置，下次提供继续入口
- 自由回答为空：不提交，提示至少输入一个要点
- 关键词不存在：不显示可点击样式
- 当日无复习题：显示完成状态并引导继续主线课程
- Web 与移动端布局：以 375～430 像素宽手机为主，Web 居中显示手机宽度内容

## 11. 测试与验收

### 单元测试

- 题目评估规则
- 节点解锁规则
- 复习日期计算
- 经验值计算
- 连续学习计算

### 组件测试

- 课程路径的三种节点状态
- 每种题型的提交与禁用状态
- 回答反馈的正确、部分正确和错误状态
- 关键词弹窗打开、关闭和状态恢复

### 手工验收

1. 新用户打开 App，能够从第一个节点开始学习。
2. 完成一节课后，节点变为完成状态并解锁下一节点。
3. 点击答案中的关键词，底部解释弹窗正常打开，关闭后答案仍在原位置。
4. 退出未完成课程后重新进入，能够从上次位置继续。
5. 修改设备日期或使用测试时钟后，到期题目进入复习队列。
6. 核心流程在 Expo Web 和至少一个手机模拟环境中可运行。

## 12. 明确不做

V0.1 不包含：

- 登录、账号和云同步
- 后端服务
- 付费与订阅
- 社区、评论和排行榜
- 语音面试
- AI 自由追问
- 公司押题
- 完整代码运行沙箱
- 动态抓取第三方面经
- 深度学习、微调、强化学习等其他世界
- 推送通知

## 13. 交付顺序

1. Expo 工程与视觉主题
2. 本地内容模型和 Transformer 示例数据
3. 首页学习路径
4. 课程播放器和基础题型
5. 结构化反馈
6. 关键词解释弹窗
7. 本地进度与复习队列
8. 完成页、空状态和测试

首个可运行里程碑只需要包含 3 个知识节点，后续再扩展至 20 个节点。这样能尽快在真实手机上验证交互，而不是先花时间填满题库。
