# Bagu 公共知识库与 AI 面试设计

## 1. 产品定位

Bagu 面向准备大模型、NLP 与通用算法岗位的校招学生，而不是只服务单个用户。产品目标是把分散的论文、课程、官方文档和真实面经，转化为可学习、可复习、可检索、可追问的结构化内容。

产品主体是学习应用，不把整个 App 定义成 AI Agent。首版采用确定性的课程、题目、复习调度和掌握度模型；后续在其中加入 AI 面试官，并在后台使用内容生产 Agent 辅助编辑。

## 2. 内容来源策略

采用“面经定优先级、权威资料写主干、经典论文做深挖”的三层来源体系。

### 2.1 面经与题库

- 牛客等公开面经用于识别高频考点、真实问法、岗位方向、公司标签和追问深度。
- 不将第三方题库正文直接复制为产品内容。
- 同一考点由多条面经交叉确认后再调整频率标签。

### 2.2 权威课程与官方文档

- Stanford CS224N、Hugging Face 官方课程和文档、PyTorch 官方文档等用于构建基础解释和工程实践。
- 这类资料负责概念定义、标准流程、代码行为和常见实践。

### 2.3 经典论文

- 由项目自行从 arXiv、会议官网、作者项目页或官方仓库收集，不要求用户手工提供。
- 第一批包括 Attention Is All You Need、BERT、LoRA、QLoRA、InstructGPT、PPO、DPO、RoPE、FlashAttention、MoE、PagedAttention 等。
- 论文用于生成动机、方法、公式、对比、局限性和论文级追问，不直接作为面试短答。
- 每条发布内容必须保留来源、章节或页码以及内容版本。

## 3. 面试内容模型

真实算法面试同时包含直接八股和项目结合型追问，因此每个主题采用双轨内容。

两条内容轨在界面上提供独立入口，在知识、掌握度和复习系统中保持关联。用户无需上传简历即可完整使用通用八股；简历上传只解锁个性化项目深挖，不作为注册或学习的前置条件。

### 3.1 通用八股轨

- 30 秒回答
- 2 分钟完整回答
- 公式与直觉
- 常见误区
- 横向比较
- 一至三级追问
- 选择题、排序题、口述题和代码题

### 3.2 项目深挖轨

- 为什么选择当前方案
- 数据来源、清洗和分布
- 训练目标、损失函数和超参数
- 指标选择及其局限
- 消融实验和备选方案
- 失败案例、资源约束和上线问题
- 如何把通用原理映射到项目决策

公共知识库提供通用项目模板。后续允许用户录入自己的项目摘要，由 AI 面试官结合模板生成个性化追问，但用户项目不进入公共知识库。

## 4. 功能模块

### 4.1 学习

学习页提供两个独立入口：

- 通用八股：按知识依赖组织学习路径，首批覆盖深度学习基础与损失函数、Transformer/NLP、预训练与微调、强化学习与对齐、训练/推理优化。
- 简历项目深挖：根据用户确认后的项目档案生成项目问题树。未上传简历时展示功能说明和可跳过的上传入口，不影响通用八股学习。

当通用知识与用户项目存在关联时，课程结束页可显示“关联我的项目”，但不把个性化题目混入公共标准答案。

### 4.2 知识库

- 按方向、主题、难度和频率浏览
- 关键词和语义搜索
- 展示短答、详解、公式、追问、关联知识和来源
- 收藏、标记掌握和加入复习
- 登录且已建立项目档案的用户可查看“与我的项目相关”，该视图只保存关联关系，不修改公共知识正文

### 4.3 复习

- 错题、低掌握度、收藏和到期内容统一进入复习队列
- 使用确定性的间隔重复算法安排时间
- 支持按主题快速复习和模拟面试复习
- AI 评分只作为掌握度信号之一，不直接覆盖用户历史
- 通用题与项目题进入同一复习队列，并使用“通用知识”“项目深挖”标签明确来源

### 4.4 我的

- XP、连续学习天数、完成课程和复习统计
- 各方向掌握度和薄弱点
- 收藏、历史记录和学习目标
- 账号、云同步和本地缓存状态
- 简历上传、解析状态、结构化项目档案和目标岗位设置
- 用户可确认、编辑、重新解析或删除项目档案

### 4.5 简历上传与项目档案

- 首版支持 PDF，后续增加 DOCX 和图片 OCR。
- 上传后提取教育、经历、项目、技术栈、数据、指标和用户职责。
- AI 提取结果必须经过用户确认，确认前不得生成正式项目问题集。
- 用户可以隐藏与面试无关的个人字段，只保留项目事实。
- 默认在用户确认结构化结果后删除原始简历，只保留加密的结构化档案；用户也可主动立即删除全部数据。
- 个性化问题集属于用户私有数据，不进入公共题库，也不用于训练公共模型。

### 4.6 模拟面试

模拟面试提供三种模式：

1. 通用八股面试
2. 简历项目面试
3. 通用八股与项目追问交替出现的综合模拟

未上传简历的用户可以使用通用八股面试；其余两种模式显示可跳过的简历入口。

## 5. 数据架构

### 5.1 内容数据库

使用 PostgreSQL 作为唯一事实来源。核心实体包括：

- `domains`：知识方向
- `topics`：主题与依赖关系
- `concepts`：定义、直觉、公式和误区
- `lessons`：课程及步骤
- `questions`：题型、答案、评分点和追问
- `sources`：论文、课程、官方文档和面经元数据
- `citations`：内容到具体来源位置的映射
- `content_versions`：草稿、审核、发布和下线状态

原始 PDF 存在对象存储中，不随 App 安装包分发。向量索引只用于语义搜索、相似内容检测和 AI 检索，不能替代结构化数据库。

### 5.2 用户数据库

核心实体包括：

- `users`
- `learning_events`
- `question_attempts`
- `concept_mastery`
- `review_items`
- `favorites`
- `streaks`
- `resumes`
- `resume_versions`
- `project_profiles`
- `project_question_sets`
- `interview_sessions`

客户端保留离线缓存，登录后与云端同步。写入采用事件记录，掌握度与复习计划可重新计算。

原始简历与结构化档案分开存储。原始文件使用短生命周期对象存储；结构化档案按用户隔离并记录用户确认版本。公共知识检索只返回公共内容，项目检索必须同时满足当前用户身份与项目档案权限。

## 6. AI Agent 边界

### 6.1 AI 面试官

AI 面试官读取目标岗位、主题掌握度、历史答案和项目档案，选择问题、评分、指出遗漏并继续追问。它不能修改公共知识内容，只能生成会话反馈和学习建议。

### 6.2 内容生产 Agent

后台流水线负责来源获取、文本提取、章节切分、知识点候选生成、题目草稿、引用绑定、重复检测和一致性检查。所有内容经过规则校验和人工审核后才发布。

### 6.3 非 Agent 能力

课程解锁、XP、复习调度、内容检索和掌握度基础计算保持确定性，确保成本、速度和可解释性。

## 7. 内容处理流程

1. 登记来源和许可信息。
2. 下载或链接权威原文，提取章节、公式和元数据。
3. 将原文切分为带来源锚点的证据块。
4. 生成概念、短答、详解、追问和练习草稿。
5. 检查引用覆盖、事实一致性、重复内容和答案可判定性。
6. 人工审核后生成发布版本。
7. 客户端通过 API 获取已发布内容，并按版本增量缓存。
8. 根据真实作答数据调整难度和频率，但不自动改写标准答案。

## 8. 质量与安全

- 标准答案必须有至少一个权威来源；高风险或存在争议的内容要求多来源。
- AI 生成内容默认是草稿，禁止未经审核直接发布。
- 引用采用短摘录和原创转述，记录版权或许可证信息。
- 用户项目、回答和学习数据默认私有，不进入公共训练语料。
- 内容需要支持勘误、回滚和版本对比。

## 9. 实施阶段

### 阶段一：结构化公开内容 MVP

- 建立六大知识方向和内容 schema
- 完成知识库、复习和我的三个页面
- 使用本地结构化数据验证完整体验
- 建立首批经典论文与权威资料清单
- 在学习页建立“通用八股”“简历项目深挖”两个入口
- 完成简历入口、项目档案和三种模拟面试模式的前端状态设计；未接入后端时明确标记为待配置能力，不伪造解析结果

### 阶段二：云端内容与账号

- PostgreSQL、对象存储和内容 API
- 登录、云同步、离线缓存和内容版本
- 内容编辑与审核后台
- PDF 简历上传、短生命周期存储、文本提取、用户确认和项目问题树生成

### 阶段三：AI 面试官

- 通用口述面试
- 项目档案与项目追问
- 基于评分点的反馈和追问
- 成本、延迟和安全控制

## 10. 验收标准

- 用户能在学习、知识库、复习和我的四个入口形成完整闭环。
- 每条知识内容可追溯到来源，并区分短答、详解和追问。
- 复习队列由真实作答和掌握度驱动。
- 用户项目数据与公共知识库严格隔离。
- 没有上传简历的用户能完整使用通用八股、知识库、复习和通用模拟面试。
- 上传简历后，用户必须确认结构化档案，才能启用项目深挖和综合模拟。
- 没有 AI 服务时，核心学习和复习功能仍可正常工作。
