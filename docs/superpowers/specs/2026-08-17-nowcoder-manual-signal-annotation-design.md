# 牛客人工面试信号标注模块设计

## 背景与目标

牛客候选页面在无 Cookie 状态下要求登录，现有公开信号采集器因此按安全策略拒绝访问。Bagu 仍希望利用其中的校招和秋招面试信号，但不能获取、保存或传递用户的牛客账号、Cookie、验证码，也不能复制牛客题干、选项、答案或帖子正文。

本模块提供一个仅在开发电脑本机运行的人工标注界面。操作者在自己的牛客标签页中登录和阅读，随后回到标注界面记录标准化的岗位、考点、追问方式和题目质量信号。标注只回答“真实面试常考什么、怎样追问”，不作为技术事实来源，也不直接生成或发布题目。

首版目标是让现有 59 条候选来源都能进入一个可恢复、可导出、可审计的人工工作流。

## 非目标

- 不自动读取牛客页面、DOM、剪贴板或浏览器标签页；
- 不接收或保存账号、密码、Cookie、Token、验证码和浏览器配置；
- 不提供粘贴原题、完整选项、答案、解析或帖子正文的输入框；
- 不抓取列表页，不自动翻页，不绕过登录、验证码、付费或访问控制；
- 不把标注数据同步到 CloudBase、产品 analytics 或正式用户账户；
- 不根据单条标注自动生成题目，不自动写入 `app/src/data`；
- 不在首版提供多人协作、权限管理、云同步或通用标注平台能力。

## 方案选择

采用独立的本地浏览器模块，由一个只监听回环地址的 Node 服务提供界面和持久化能力。

没有选择直接编辑 CSV，因为枚举字段、进度恢复和必填校验容易出错；没有集成进正式 Expo App，因为这是开发期研究工具，会增加移动端产品包和用户数据边界的复杂度；没有使用浏览器扩展，因为扩展需要页面权限，容易造成读取登录态或正文的误解与风险。

## 系统边界

模块与正式 App、现有自动采集器和题库保持单向、文件级隔离：

```text
pilot-100.json 候选清单
  -> 本地标注服务（仅 127.0.0.1）
  -> 浏览器标注界面
  -> 本地人工标注 JSON
  -> CSV 与考点汇总导出
  -> 后续原创出题优先级输入
```

“打开来源”只使用普通外部链接打开牛客页面。牛客登录和阅读完全发生在牛客自己的标签页中；标注模块不注入脚本、不读取页面内容、不共享登录状态。

自动采集状态与人工标注状态相互独立。即使来源因 `login_required` 被自动采集器拒绝，例如 `nc-i-004`，仍可由操作者在自己的登录标签页中人工查看并标注。人工标注不得反向把该来源改为自动采集器的 `approved`。

## 模块组成

### 本地服务

本地服务负责：

- 只绑定 `127.0.0.1`，拒绝局域网和公网监听；
- 读取既有 `pilot-100.json`，向界面返回最小候选字段；
- 校验人工标注请求，拒绝未知来源 ID、未知枚举和额外字段；
- 使用临时文件加原子替换持久化标注；
- 生成 JSON、CSV 和考点汇总；
- 限制请求体大小，并校验本地 Origin 与 Host；
- 不提供任意 URL 抓取、文件路径读取或代理能力。

### 浏览器界面

界面是安静、紧凑的内部工具，不复用正式 App 的学习路径界面。主要区域包括：

- 顶部进度：总数、已完成、待处理、跳过；
- 候选列表与状态筛选；
- 当前来源信息和“打开来源”命令；
- 标准化标签表单；
- “保存并下一条”、上一条和跳过命令；
- 导出与汇总入口。

页面重新打开时定位到首个未完成来源；也允许返回并修改已经完成的记录。

## 标注数据模型

每条人工标注包含：

- `schemaVersion`：首版固定为 `1`；
- `sourceId`：必须存在于候选清单；
- `status`：`pending | completed | skipped`；
- `relevance`：`relevant | not-relevant | uncertain`；
- `role`：`llm_algorithm | llm_application | shared | unknown`；
- `recruitingStage`：`campus-autumn | campus-other | unknown`；
- `topicIds`：从既有考点枚举中多选；
- `followUpTypes`：原理、边界、排障、指标、系统设计、方案权衡，多选；
- `misconceptionTypes`：概念混淆、条件遗漏、因果倒置、复杂度误判、指标误用，多选；
- `choiceSignals`：仅选择题来源使用，记录认知层级、干扰项问题和答案线索类型；
- `summary`：操作者自己的概括，最多 100 个字符；
- `skipReason`：仅跳过时使用固定枚举和可选短备注；
- `updatedAt`：最后保存时间。

完成状态要求相关性、岗位和至少一个考点已明确。选择题若标为相关，还需要填写认知层级。无法确认时应使用 `uncertain` 或 `skipped`，不得为了完成率编造标签。

`summary` 不是原题摘录字段。界面明确提示不得复制题干、选项、答案、解析、作者信息或连续原句。保存前检查手机号、邮箱、微信、QQ 等明显个人信息模式；命中时拒绝保存并要求改写。首版不声称能够通过自动规则证明文本完全原创，因此导出仍保留人工复核要求。

## 标注流程

1. 启动本地模块，载入 59 条候选来源和既有进度。
2. 点击“打开来源”，由默认浏览器打开牛客页面。
3. 操作者在自己的牛客会话中阅读，不向模块提供登录信息。
4. 返回模块，判断相关性并勾选标准化标签。
5. 可选填写一句自己的短概括。
6. 点击“保存并下一条”；服务完成校验和原子写入。
7. 页面移动到下一个未完成来源。
8. 全部或部分完成后导出标注和考点汇总。

来源打不开、内容太少、与目标岗位无关或无法判断时可以跳过，并记录标准化原因。跳过记录计入进度，但不进入考点频次。

## 本地存储与导出

人工标注写入独立的、默认被 Git 忽略的本地数据目录。源候选清单仍由版本控制管理，人工结果不默认提交。

导出包括：

1. `annotations.json`：完整结构化人工标注；
2. `annotations.csv`：便于人工复查的表格视图，正确转义逗号、引号、换行并防止公式注入；
3. `topic-summary.json`：按岗位、考点、追问类型、来源类型统计的频次和覆盖缺口；
4. `annotation-report.json`：完成、跳过、待处理、无关和不确定数量。

所有统计以唯一 `sourceId` 为单位。同一来源对同一考点最多贡献一次。`pending`、`skipped`、`not-relevant` 和 `uncertain` 不进入高频考点排名，但保留在报告分母中。

## 下游使用规则

标注输出只能用于确定选题优先级和追问形式。后续题目生产必须经过：

```text
人工面试信号
  -> 高频考点与覆盖缺口
  -> 官方文档、论文和许可合适的开源项目核实
  -> AI 原创候选题
  -> 证据 reviewer
  -> 题目质量 reviewer
  -> 确定性质量门禁
  -> 手机人工终审
  -> 正式题库
```

牛客信号不能用来证明答案正确。候选题不得引用或改写得可还原某一牛客原题。任何自动化步骤都不能绕过人工终审，也不能直接把标注导入正式课程。

## 错误处理

- 候选清单无效：拒绝启动并指出具体来源和字段；
- 标注文件不存在：创建空的版本化数据集；
- 标注文件损坏：停止写入，保留原文件并提示从最近导出恢复；
- 保存校验失败：保留当前表单，不移动到下一条；
- 原子替换失败：报告错误，旧文件保持可读；
- 未知来源或枚举：拒绝请求，不静默丢弃；
- 外部链接打开失败：允许复制规范化 URL 或标记跳过；
- 导出失败：不影响已保存标注，允许重试。

## 测试策略

自动测试覆盖：

- 59 条候选载入、唯一 ID 和顺序稳定性；
- 新建、修改、完成、跳过和恢复首个未完成位置；
- 必填条件、选择题条件字段、未知枚举和额外字段拒绝；
- 100 字限制与明显个人信息拦截；
- 原子写入失败时旧数据不损坏；
- JSON、CSV、汇总和报告计数一致；
- CSV 公式注入与 RFC 4180 转义；
- 跳过、无关和不确定来源不贡献频次；
- 服务仅监听回环地址，并拒绝异常 Host、Origin 和过大请求体；
- 模块没有牛客网络请求、Cookie 读取或正式题库写入路径。

交互验收使用桌面浏览器完成完整的打开、标注、保存、重启恢复和导出流程，并在窄屏视口检查无溢出、无遮挡和按钮可操作。正式 App 仍需通过既有 TypeScript、lint、Expo Doctor、内容与题目质量测试，证明该开发工具没有影响产品运行时。

## 验收标准

- 现有 59 条候选来源都能在模块中找到并打开；
- 完成、待处理和跳过统计准确；
- 关闭并重新启动后恢复所有已保存结果和首个未完成位置；
- 标注文件不包含登录信息、Cookie、帖子正文、完整题干、选项或答案字段；
- JSON、CSV、考点汇总和报告可以重复生成且统计一致；
- 本地服务无法被局域网设备访问，不具备任何牛客抓取能力；
- 标注结果与自动采集审批状态、正式 App 数据和题库保持隔离；
- 任何标注结果都不能绕过证据核验、双 reviewer、质量门禁和手机人工终审。
