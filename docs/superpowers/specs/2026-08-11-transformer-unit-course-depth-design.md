# Transformer Unit 课程深度重构设计

## 背景与目标

当前课程数据把一条 Transformer 学习路径建模为 `CourseSection -> CourseUnit -> Lesson`，界面上因此出现多个只有两个节点的 Unit。用户期望的产品语言是：Transformer 本身是一个 Unit，QKV、Transformer Block、位置与长上下文等主题是 Unit 下的 Section，每个 Section 再包含足以形成一屏路径的学习节点。

本轮同时解决四类问题：答题进度不直观、iPhone/Expo Go 音效不可靠、路径节点不是完整圆形、课程和知识库内容不足。

## 已选方案与备选方案

采用“丰富题库、短会话动态抽题”方案：每个节点首批维护 12 道题，每次闯关确定性抽取 8 道；答错题在本轮末尾追加一次复练。它兼顾内容厚度和手机端单次练习时长。

不采用以下方案：

- 每节点固定做完全部题目：内容完整，但单次会话过长，扩题后体验会持续恶化。
- 每节点只保留 4 道固定题：开发简单，但重复性强，无法支撑错题复练和长期扩充。
- 首版一次性写满 20 道题：内容成本过高且不利于先验证交互；数据结构仍需允许后续无迁移扩展到 20 道以上。

## 课程层级与内容范围

课程模型改为：

```text
Course
└── Unit: Transformer
    ├── Section 1: QKV 与注意力计算
    ├── Section 2: 多头、Mask 与 Transformer Block
    ├── Section 3: 位置编码与长上下文
    ├── Section 4: Encoder、Decoder 与模型架构
    └── Section 5: KV Cache 与高效推理
        └── 每个 Section 5 个 LearningNode
            └── 每个节点首批 12 道 Exercise
```

首批规模为 1 个 Unit、5 个 Section、25 个节点、300 道练习题。每个节点覆盖一个可在 8–12 分钟内掌握的小目标，而不是直接等同于一个大知识点。题型继续包含单选、多选、排序和口述自评；每个节点至少包含两种客观题型，并至少包含一道面试口述题。

`Unit` 持有全局主题、配色和总体进度；`Section` 持有小主题、说明和节点列表；`LearningNode` 持有标题、图标、时长、题库和内容标签。旧的 `Lesson` 语义迁移为 `LearningNode`，持久化仍使用稳定的节点 ID，已有完成记录能继续识别匹配的 ID。

## 学习路径与圆形节点

首页直接展示 Transformer Unit 的学习路径。每个 Section 有紧凑的主题横幅，横幅之后显示 5 个错落排列的圆形节点，确保一个主题在手机上形成清晰、连续的路径。

节点由两个同尺寸圆形图层组成：底层圆向下偏移形成厚度，顶层圆显示图标和状态。两个图层都使用相同宽高与半径，不再使用带直边的胶囊或圆柱侧面。完成、当前、锁定三种状态通过颜色、图标和透明度区分；阴影不承担状态表达。

## 练习会话、进度和错题复练

进入节点时，由纯函数 `buildPracticeSession(node, attemptSeed)` 创建本次题目序列：

1. 从节点题库选取 8 道基础题，保证题型和知识标签尽量均衡。
2. 用户提交答案后记录结果；答错题的 ID 进入本次复练队列。
3. 基础题完成后，把每道错题追加一次到队尾；同一道题在追加复练中不再无限追加，防止死循环。
4. 全部基础题和追加复练结束后进入完成页并结算 XP。

进度条按“已完成题数 / 当前会话总题数”显示，并在提交答案后前进。追加错题时分母同步增加，因此不会回退或超过 100%。进度更新使用 React Native Animated 的宽度/缩放动画；旁边显示 `当前序号/总题数`，便于验证进度确实变化。退出后重进首版重新生成会话，不实现中途恢复，避免扩大本次范围。

抽题首版使用稳定轮换而不是不可预测随机：以节点历史尝试次数作为 seed，在 12 道题中轮换选取 8 道。这样既能变化题目，也便于测试与复现。未来增加熟练度模型时可替换选题器，不改页面接口。

## 音效架构

移除页面级音频播放器，改为根布局中的全局 `SoundProvider`。Provider 只暴露 `playCorrect()`、`playWrong()` 和 `playComplete()`，统一持有三段本地 WAV 的播放器。

Provider 在播放器已加载且用户开启音效时才播放；快速重复触发时先回到开头再播放。加载失败或 iOS 拒绝播放时只在开发环境记录错误，不阻塞提交、进度、XP 或导航。根布局初始化符合 Expo SDK 54 的音频模式，遵循 iPhone 静音开关。音效开关继续使用现有持久化字段，旧用户缺少字段时默认开启。

验收时分别覆盖答对、答错、完成和关闭音效四条路径，并确认完成音效每次完成流程只播放一次。

## 知识库呈现与扩充

知识库继续与做题路径分离，采用“概念文章卡”而不是把练习题复制过去。每个条目包含：一句话结论、直觉解释、公式或计算流程、面试回答框架、易错点、追问、关联概念和来源。详情页通过目录化小节与关键词弹窗降低连续长文字的压力。

Transformer 首批知识覆盖与 25 个学习节点一一对应，并补充跨节点总览条目。内容以经典论文和官方技术文档为事实来源；开源面试仓库只用作主题查漏清单。所有中文解释和题目均在项目中原创编写，不复制第三方教程正文。来源至少覆盖：

- *Attention Is All You Need*：缩放点积、多头注意力、Encoder/Decoder、位置编码。
- BERT、GPT 系列与 T5 原始论文：Encoder-only、Decoder-only、Encoder-Decoder 与训练目标。
- RoPE、ALiBi：相对位置与长度外推。
- FlashAttention：精确注意力的 IO 优化。
- GQA、MQA 与主流推理文档：KV Cache、Prefill/Decode 和缓存容量。

知识库搜索按标题、别名、摘要、关键点和关联概念匹配。首版不引入远程数据库或在线生成，数据随 App 打包，确保 Expo Go 离线可用并避免内容版本不可控。

## 组件边界与数据流

- `types/course.ts`：只定义 `Course`、`CourseUnit`、`CourseSection`、`LearningNode` 和练习类型。
- `data/transformer/`：按 5 个 Section 拆分题库与节点数据，入口文件只负责组合和导出，避免单个文件继续膨胀。
- `utils/practice-session.ts`：负责选题、追加一次错题复练、进度计算；不依赖 React 或路由。
- `context/sound-context.tsx`：负责音频生命周期和语义播放接口。
- `course-path.tsx`：只负责 Unit/Section 布局与节点状态，不处理答题逻辑。
- `lesson/[id].tsx`：消费已经构造好的会话并渲染题型；不直接持有音频播放器。
- `knowledge-base.ts`：组合知识条目并提供查询，不混入练习会话状态。

数据流是“静态课程数据 -> 路径选择节点 -> 构造练习会话 -> 提交结果 -> 更新会话进度/复练队列 -> 完成后写入持久化进度”。音效由提交结果和完成事件旁路触发，不参与业务状态计算。

## 错误处理与兼容性

- 课程数据缺失或节点 ID 无效时显示可返回首页的错误页，不访问未定义题目。
- 题库少于 8 道时使用全部题目并保持正确分母；空题库禁止进入并在开发检查中报错。
- 老版本完成记录中的节点 ID 保留；无法匹配的 ID 忽略，不导致进度加载失败。
- 音效未加载、播放失败或资源不可用时静默降级。
- 主要目标仍是 iPhone + App Store 版 Expo Go + Expo SDK 54，同时保持 Expo Web 可运行。

## 测试与验收

静态数据检查验证：恰好 1 个 Transformer Unit、5 个 Section、每 Section 5 个节点、每节点至少 12 道题；所有节点 ID、题目 ID 唯一；选择题答案有效；排序题答案完整；关键词和知识关联能够解析。

会话逻辑测试验证：12 题池稳定抽取 8 题、不同 attempt seed 能轮换题目、错题只追加一次、全对时总题数保持 8、答错时分母增加且进度单调递增、最终恰好 100%。

界面验收验证：

1. 首页打开即看到 Transformer 学习路径，Section 层级名称正确，每个 Section 有 5 个圆形节点。
2. 节点上下两层均为完整圆形，无胶囊直边或黑色下边框。
3. 每提交一道题，进度条有可见变化；错题复练时计数正确。
4. 答对、答错、完成分别播放不同音效；关闭开关后均不播放。
5. 知识库不是答题列表，并能从概念总览进入结构化详情。
6. TypeScript、ESLint、数据校验、Expo Doctor、Web 构建和 iOS bundle 检查通过。

## 非目标

本轮不实现账号系统、云端题库、AI 在线出题、跨设备同步、社区、排行榜和完整记忆曲线算法。它们可以建立在本轮稳定的课程层级、选题器和持久化 ID 之上，但不会阻塞本轮交付。
