# 牛客公开内容信号采集设计

## 背景与目标

Bagu 需要利用真实校招、秋招面经和公开选择题扩大选题覆盖，但不能把牛客内容复制为自己的题库。本项目第一版以 100 个公开页面为试采规模，面经与选择题页面各约 50 个，只生成结构化的“考点候选包”。候选包用于确定后续原创命题的优先级，不自动生成题目，也不直接修改正式课程。

目标岗位限定为：

- 大模型算法工程师；
- 大模型应用工程师。

## 不在范围内

- 不遍历牛客列表页或整站抓取；
- 不访问需要登录、付费、验证码或其他访问控制的页面；
- 不携带 Cookie、账号 Token 或浏览器登录状态；
- 不保存原帖全文、原题题干、完整选项、图片或附件；
- 不保存用户名、简历、联系方式或其他个人信息；
- 不自动生成题目，不自动写入正式题库；
- 不部署常驻云端爬虫或定时任务。

## 方案选择

采用本地 TypeScript 受控清单采集器。搜索引擎只负责发现候选链接，候选链接写入清单并经过人工确认；只有状态为 `approved` 的 URL 才能进入采集。

不采用完整爬虫框架。当前试采只有 100 页，代理池、浏览器渲染、自动翻页和分布式调度会增加访问风险、许可成本与维护复杂度。也不采用纯人工复制，因为它无法稳定执行脱敏、去重和主题统计。

实现概念参考：

- [Mozilla Readability](https://github.com/mozilla/readability)：用于无脚本正文抽取，Apache-2.0；
- [robotstxt-util](https://github.com/muratgozel/robotstxt-util)：用于按 RFC 9309 解析 `robots.txt`，MIT；
- 外部项目只作为结构和实现依据，不复制其业务数据或受限制内容。

## 系统边界

采集器属于开发期研究工具，放在 App 运行时之外。它不能被移动端用户调用，也不进入 Expo 包、CloudBase 云函数或匿名分析链路。

数据流如下：

```text
搜索结果
  -> 候选 URL 清单
  -> 人工批准
  -> robots / 域名 / 页面类型检查
  -> 单线程低频下载
  -> 内存正文解析
  -> 脱敏、内容哈希与去重
  -> 考点和追问信号
  -> JSON / CSV 候选包与汇总报告
```

## 候选清单

候选清单记录：

- 唯一来源 ID；
- 规范化 URL；
- `interview` 或 `multiple-choice` 页面类型；
- `discovered`、`approved` 或 `rejected` 审批状态；
- 搜索关键词和发现时间；
- 可选人工备注。

采集前验证：

- URL 必须为 HTTPS；
- 主机必须属于允许清单；
- URL 不得包含访问 Token、用户邮箱或其他敏感查询参数；
- 同一规范化 URL 只能出现一次；
- 最多批准 100 个页面；
- 面经与选择题目标数量各约 50 个，允许因合规拒绝产生小幅偏差。

## 合规抓取

抓取器使用明确的研究用途 User-Agent，单线程运行，每次请求间隔 8–12 秒。每个来源在请求前检查 `robots.txt`，并设置连接超时、正文大小上限和重定向上限。

以下情况立即拒绝：

- `robots.txt` 不允许访问；
- 页面要求登录、付费或验证码；
- 重定向到未授权域名；
- 页面类型不在范围内；
- 返回内容不是 HTML；
- 内容大小超出上限；
- 无法确认页面是否公开。

网络错误最多重试一次，并继续服从请求间隔。工具不使用代理、不轮换身份、不伪装普通用户，也不尝试绕过限制。

## 临时正文处理

HTML 只存在于进程内存。DOM 环境关闭脚本执行和外部资源加载，正文抽取结果只供本次结构化处理使用。处理结束后不写入 HTML、Markdown、正文缓存或调试快照。

采集器可以短暂读取标题、正文和结构信息，以完成：

- 页面类型确认；
- 岗位、年份、招聘阶段识别；
- 考点关键词与追问模式识别；
- 选择题干扰项错误类型归纳；
- 内容哈希去重。

## 脱敏与最小化

结构化之前先检测并移除：

- 中国大陆及国际手机号；
- 邮箱地址；
- 微信号、QQ 号和私人联系方式提示；
- 简历、姓名、昵称、头像说明和个人主页标识；
- 内推码、群链接及不影响考点判断的公司人员信息。

第一版使用确定性规则完成脱敏。输出层只接受预定义字段，任何未映射自由文本默认丢弃。这样即使正文中存在未识别的个人信息，也不会因为通用 `rawText` 或 `excerpt` 字段被写入候选包。

## 考点信号模型

每条处理成功的来源记录只包含：

- 来源 ID、URL、页面类型、采集时间和内容哈希；
- 目标岗位标签；
- 校招、秋招或未确定的招聘阶段；
- 年份或未确定状态；
- 标准化考点 ID 列表；
- 追问类型，例如原理、边界、排障、指标、系统设计或方案权衡；
- 常见误区类型，例如概念混淆、条件遗漏、因果倒置或复杂度误判；
- 信号置信度与人工复核状态。

选择题页面额外允许记录：

- 认知层级候选；
- 干扰项错误类型；
- 是否存在答案位置、长度、措辞或格式线索。

禁止记录原始题干、选项文字、正确答案文字和原解析。

## 候选包输出

产物包括：

1. `source-signals.jsonl`：逐来源结构化信号；
2. `source-signals.csv`：便于人工筛选；
3. `topic-summary.json`：按岗位和考点汇总频率；
4. `intake-report.json`：成功、拒绝、重复和失败统计；
5. `rejected-sources.jsonl`：仅记录 URL、拒绝代码和时间，不记录正文。

候选包给出补题优先级建议，但不会直接调用题目 builder。被采用的考点仍需经过原创命题、一级证据核验、确定性门禁、双 reviewer 和手机人工标注。

## 状态与停止条件

每个页面只能进入以下终态之一：

- `processed`；
- `blocked_by_robots`；
- `login_required`；
- `captcha_detected`；
- `unsupported_page`；
- `redirect_blocked`；
- `response_too_large`；
- `duplicate`；
- `insufficient_signal`；
- `network_failed`。

达到任一条件即停止本轮：

- 已处理或明确拒绝 100 个批准页面；
- 连续 10 个页面被访问控制拒绝；
- 最近 20 个页面中网络或解析错误超过 50%；
- 操作员主动中止。

中止后仍生成当前批次报告，便于判断是否调整来源发现方式。

## 测试策略

自动测试只能使用本地 HTML fixture，不请求牛客：

- `robots.txt` 允许、拒绝和无法获取时的保守处理；
- URL 规范化、域名白名单和敏感查询参数拒绝；
- 登录页、验证码和付费页识别；
- Readability 正文提取和无脚本执行；
- 手机号、邮箱、微信号、QQ 和简历信息脱敏；
- 输出 Schema 不允许原文、题干和完整选项字段；
- 内容哈希和规范化 URL 去重；
- 算法岗、应用岗和招聘阶段分类；
- 考点、追问与误区映射；
- 多选题认知层级和线索类型提取；
- 100 页上限、请求间隔和错误率停止条件；
- JSONL、CSV 和汇总统计一致性。

试采前还需执行一次只访问 `robots.txt` 和单个已批准页面的人工烟测。发现访问规则不明确时，默认不采集。

## 验收标准

- 只有人工批准且访问规则允许的页面会发起正文请求；
- 不使用登录态、代理或访问控制绕过；
- 100 页上限和低频单线程策略可由测试验证；
- 所有输出均通过严格 Schema；
- 输出中不存在原帖正文、原始题干、完整选项或个人信息字段；
- 相同页面不会重复贡献考点频率；
- 每条信号可以通过来源 URL 回溯；
- 候选包不会自动修改 App 题库；
- 失败和拒绝原因完整可审计。

## 后续边界

第一批 100 页完成并人工复核后，再决定是否增加页面数量、引入模型辅助分类或申请牛客内容授权。任何自动命题、长期增量采集或云端调度都需要新的设计评审，不能由本项目默认扩展。
