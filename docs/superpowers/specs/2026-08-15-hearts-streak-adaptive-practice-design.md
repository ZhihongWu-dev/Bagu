# Bagu 生命值、连续学习与自适应练习设计

## 状态

已由产品负责人于 2026-08-15 确认。

## 背景

Bagu 当前已经具备课程节点、练习会话、错题追加、课程进度和 XP，但首页连续学习天数与专注值仍是占位数据，课程答题页也没有生命值反馈。当前每节课固定抽取 8 道题，无法根据用户在同一知识节点上的近期表现调整练习长度。

本设计为学习主流程增加三项互相配合但职责分离的能力：

- 单次课程内的 5 点生命值；
- 以完整课程为依据的连续学习天数；
- 基于节点近期表现的 8、10、12 题自适应练习。

XP 继续保留为经验值，不作为货币，不出现宝石、商店、购买生命或其他消费入口。

## 目标

- 让用户在答题过程中明确感知错误成本和剩余机会。
- 用简单、可信的连续学习记录鼓励每天完成一节课。
- 在不增加复杂设置的情况下，使练习长度匹配用户近期表现。
- 保持课程主流程即时、低文本，并兼容 Expo Go。
- 让激励规则成为可测试的领域逻辑，不散落在页面组件中。
- 保留旧用户现有课程进度、错题、收藏、设置和 XP。

## 非目标

- 不实现宝石、商店、订阅、付费无限生命或广告换生命。
- 不实现生命值定时恢复、练习回血、好友赠送或跨课程累计。
- 不实现 streak freeze、补签、排行榜或社交分享。
- 不在本次工作中扩充题库、资料库或增加题目难度标签。
- 不复制 Duolingo 的图标、角色、插画、动画、代码或品牌识别。
- 不要求登录、联网或云端同步。

## 参考研究

实现前调研了公开的 Duolingo 风格学习项目：

- `code-with-antonio/nextjs-duolingo-clone` 展示了 hearts、无生命弹层、练习回血和商店之间的产品关系。它与 Bagu 技术栈不同，且仓库页面没有提供足够明确的可复用许可信息，因此只用于理解交互机制，不复用代码或资产。
- `abdulkadir-erdeger/duolingo-clone` 是较早的 React Native/Expo 示例，可用于确认移动端顶部状态信息的布局方向，但状态模型较简单且许可不明确，同样不复用代码或资产。

调研结论是沿用 Bagu 现有 React Context、本地持久化、练习会话生成器和 `AppIcon` 体系，不引入新的游戏化框架，也不采用外部项目的视觉资产。

## 产品规则

### 生命值

- 每次新建课程会话从 5 点生命开始。
- 每次普通题答错扣 1 点；答对不变化。
- 自我回忆题不扣生命。
- 答错的题仍按现有规则追加一次复习。
- 一次题目提交最多扣 1 点，重复渲染或状态更新不得重复扣除。
- 生命归零时立即结束本轮，不再进入后续题目或追加复习。
- 失败、中途退出均不结算 XP、streak 或节点表现。
- 重新挑战恢复到 5 点生命，沿用本轮基础题 ID，可重新排列顺序。
- 关闭课程后再次进入视为新会话，生命恢复为 5。

生命值只表达当前课程状态，不写入长期持久化。产品没有生命消费或付费恢复，因此不需要防止用户通过重新进入课程恢复生命。

### 连续学习

只有完整完成至少一节课程才能维持 streak：

- 从未完成过课程：完成后为 1 天。
- 上次完成日期就是今天：保持当前天数，不重复增加。
- 上次完成日期是昨天：当前天数加 1。
- 中断一天或以上：下一次完成时重置为 1。
- 失败、中途退出和仅浏览内容都不更新 streak。
- 不提供冻结、补签或回溯修改。

日期使用课程完成时的设备本地日历日期 `YYYY-MM-DD`，而不是两个时间戳是否相差 24 小时。跨午夜完成按完成时所在日期计算，跨月、跨年和夏令时切换均按本地日历相邻日判断。

若检测到上次完成日期晚于当前本地日期，保持现有 streak 且不发放新增天数，避免设备时间回拨造成重复奖励。等本地日期追平或超过记录日期后再恢复正常计算。

### XP

- XP 保留为学习经验累计值。
- 只有完整完成课程才结算 XP。
- XP 可出现在完成页和个人页，不占用首页顶部的核心状态位置。
- 移除以宝石图形表达 XP 的方式，改用明确的 `XP` 文本或经验相关图标。
- 移除没有真实计算来源的 `focus` 占位状态。

## 自适应练习

### 题量分档

题量按当前节点最近 5 次完整课程的基础题首次作答正确率决定：

| 条件 | 基础题量 | 选择重点 |
| --- | ---: | --- |
| 没有历史记录 | 10 | 未做过或使用次数较少的题 |
| 正确率低于 70% | 8 | 优先覆盖近期错题，再补充较少使用的题 |
| 正确率为 70% 至 89% | 10 | 混合近期错题、未做题和较少使用的题 |
| 正确率达到 90% | 12 | 优先未做题和使用次数较少的题 |

当前题目没有统一难度标签，因此首版不声称按难度选题。后续题库扩充项目增加可靠的难度元数据后，可在 12 题档中优先加入较难题，但不得改变本设计的题量和完成规则。

### 正确率口径

- 只统计本轮基础题的首次有效作答。
- 追加的错题复习不进入正确率分子或分母。
- 同一道题在同一基础会话中只记一次。
- 自我回忆题按完成处理，但不用于客观正确率；它既不进入分子，也不进入分母。
- 如果一轮没有可计分的客观题，则不写入节点表现记录。
- 最近正确率为最近最多 5 条有效记录的 `correct / total` 汇总值，而不是各轮百分比的简单平均。

### 题目选择稳定性

- 选择器必须是纯函数，输入为节点题池、近期表现、题目使用记录和会话种子，输出为基础题 ID 列表。
- 相同输入和种子产生相同题目集合，方便失败后重试及测试。
- 题池不足时返回全部可用唯一题目，不复制题目来凑齐目标数量。
- 近期错题不存在或数量不足时，用未做题和使用次数较少的题补足。
- 失败后的“重新挑战”复用基础题 ID，仅允许调整顺序；从课程列表重新进入则生成新会话。

## 界面与交互

### 首页

首页顶部只显示一个清晰的小火苗和当前连续天数：

- 使用 Bagu 自有的双层实心火苗，橙色外焰、黄色内焰。
- 不使用状态卡片、背景胶囊、宝石或多资源状态栏。
- 火苗与数字形成单个紧凑状态项，不抢占课程路径的视觉层级。
- 数字使用等宽数字特性，天数变化不应造成明显布局跳动。

### 答题页

顶部从左到右为：退出按钮、课程进度条、生命图标与剩余数量。题号移到题目内容区域的小型标签中，避免右侧同时出现两个计数器。

答错时：

- 当前心形短暂缩放或抖动；
- 数字立即减 1；
- 沿用现有错误音效和答案反馈；
- 动画不阻塞状态提交，用户开启减少动态效果时可省略位移动画。

生命归零后进入独立失败状态，显示本轮进度和错题数，主操作为“重新挑战”，次操作为返回课程路径。不加入倒计时、购买或解释性长文案。

### 完成页

完整完成课程后显示本轮 XP；如果这是当天首次有效完成，同时显示 streak 更新结果。同日重复完成不制造“连续天数增加”的假反馈。

## 架构

采用独立的学习激励领域模块，页面负责渲染和派发动作，不直接实现日期或选题规则。

建议职责如下：

```text
lesson screen
  -> lesson run state (transient hearts and answer ledger)
  -> learning motivation domain
       - applyHeartPenalty
       - calculateStreak
       - calculateRecentAccuracy
       - selectPracticeLength
       - buildAdaptivePracticeSession
  -> progress context
  -> progress storage
```

`lesson run state` 保存本轮生命、基础题 ID、首次作答账本、追加复习和失败状态。它随课程页面生命周期存在，不进入全局持久化。

`learning motivation domain` 由无副作用函数组成，不读取系统时间、React 状态或存储。调用方显式传入本地日期和历史记录，保证规则可单元测试。

`progress context` 在课程完整完成时进行一次原子式结算：更新课程进度、XP、streak、节点表现和题目使用记录。单个字段失败时不得留下“XP 已增加但课程未完成”之类的半结算状态。

## 数据模型与迁移

持久化数据新增等价于以下结构的字段：

```ts
type LearningStreak = {
  current: number;
  lastCompletedLocalDate: string | null;
};

type NodePerformanceEntry = {
  completedAt: string;
  correct: number;
  total: number;
  incorrectExerciseIds: string[];
};

type NodeLearningStats = {
  recentSessions: NodePerformanceEntry[];
  exerciseUseCounts: Record<string, number>;
};

type LearningMotivationProgress = {
  streak: LearningStreak;
  nodeStats: Record<string, NodeLearningStats>;
};
```

实现可以根据现有 `PersistedProgress` 结构调整命名，但必须保持以下约束：

- 每个节点只保留最近 5 条表现记录。
- 错题只保存内部 exercise ID，不复制题目或答案正文。
- 使用次数只为实际进入基础会话的题增加。
- 新字段缺失时迁移为 streak `0/null` 和空节点记录。
- 无法识别或越界的计数归一化为安全值；无效日期按没有历史日期处理。
- 迁移不得覆盖现有完成节点、节点尝试次数、XP、复习队列、收藏和设置。

## 故障处理

- 持久化加载失败时，激励数据回退为默认值，核心课程仍可进入。
- 题池为空时不创建无法完成的课程，返回课程路径并显示现有通用错误状态。
- 题池少于目标题量时使用全部唯一题目，并继续允许正常完成。
- 快速重复点击提交按钮时，只接受第一次有效提交，防止重复扣生命或重复记分。
- 应用进入后台再返回时保留当前内存中的本轮状态；进程被系统终止后则开启新会话。
- streak、XP 或表现结算发生异常时，不让完成按钮卡死；记录开发环境错误并在下一次持久化时使用完整快照重试。

## 可访问性

- 心形和火苗不能只靠颜色表达，均提供可读标签，如“剩余 4 点生命”和“连续学习 12 天”。
- 生命数字和图标满足触控界面常见对比度要求，但它们本身不是可点击按钮。
- 动态字号下，顶部使用稳定宽度并允许题号标签在内容区换行，不与退出按钮或进度条重叠。
- 减少动态效果开启时，扣生命只使用颜色和数值变化，不执行明显抖动。

## 验收标准

### 领域单元测试

- 5 次普通错答依次降到 0，且单次提交不会重复扣除。
- 自我回忆题不扣生命，也不污染客观正确率。
- 最近正确率边界 `69.x%`、`70%`、`89.x%`、`90%` 分别得到正确题量。
- 最近记录超过 5 条时只使用最新 5 条。
- 无历史、题池不足、无错题和无客观题时返回确定且有效的结果。
- streak 覆盖首次完成、同日重复、相邻日、断签、跨月、跨年和未来日期记录。

### 集成测试

- 答错追加复习，生命归零后停止课程并可重新挑战同一题集。
- 中途退出和失败不改变 XP、streak 或节点表现。
- 完整完成通过一次结算同时更新课程进度、XP、streak 和节点表现。
- 旧版持久化数据升级后原有数据保持不变。
- 首页不再显示硬编码 streak、宝石 XP 或 focus 占位值。

### 设备验证

- 在 iPhone 优先的窄屏与常见 Android 尺寸验证首页火苗和课程顶部栏不重叠。
- 在 Expo Go 中完成一轮成功、一轮生命归零和一次重试。
- 运行 TypeScript、lint、Expo Doctor 和相关测试。
- 验证前后台切换、冷启动及系统减少动态效果设置。
