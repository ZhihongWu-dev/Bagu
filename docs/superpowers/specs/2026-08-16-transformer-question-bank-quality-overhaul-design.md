# Transformer 公共题库质量重构设计

## 背景

Bagu 的 Transformer 公共课程包含 25 个学习节点，每个节点 12 道题，共 300 道题。现有题库已经覆盖主要知识点，但部分题目由通用模板批量生成，出现答案泄露、干扰项明显错误、题干与解析错位以及只考察表面记忆的问题。

本轮保留现有 25 个节点、稳定节点 ID、练习会话和 8/10/12 自适应题量，重新审查并编写全部 300 道题。目标不是提高文字复杂度，而是让题目真正测量理解、推理和面试表达能力。

## 目标与非目标

### 目标

- 逐题重写 300 道 Transformer 公共课程题目。
- 每道题有单一、明确且可验证的能力目标。
- 公式题要求推导、判断或诊断，不允许照抄页面已展示公式。
- 干扰项来自真实误区，并与正确项处于同一语义层次。
- 解析解释结论、机制、选项差异和适用边界。
- 每道题关联可靠来源和内容标签。
- 建立自动质量门禁，阻止同类低质量题再次进入题库。
- 建立相互隔离的命题、证据审查和命题质量审查角色，保留结构化审计记录。
- 建立仅测试阶段可见的手机标注模式，让真实用户完成全量作答与体验标注。
- 保持 iPhone 优先、Expo Go 兼容和离线答题。

### 非目标

- 不加入手写代码题。
- 不在运行时调用大模型临时生成题目。
- 不把审题 Agent 或手机标注工具放入正式用户的学习流程。
- 不改变课程节点顺序、生命值、streak、XP 或解锁规则。
- 不直接复制 GitHub、牛客或其他面经原题。
- 不将题库包装成标准化职业资格考试。

## 依据与来源层级

知识正确性按以下顺序交叉验证：

1. 原始论文，例如 Transformer、RoPE、ALiBi、FlashAttention 和 PagedAttention。
2. 官方技术报告，例如 Qwen、DeepSeek 及相关模型架构报告。
3. 官方实现和文档，例如 PyTorch、Hugging Face Transformers、vLLM。
4. 活跃维护且许可证清晰的开源实现，用于确认工程行为、版本差异和常见边界。
5. GitHub 与牛客公开面经只用于聚合高频主题、问法和追问链，不作为事实正确性的唯一来源，不复制个人经历或原文。

关键技术结论至少有一个一手来源；易受版本影响的工程结论还需一个当前官方实现或文档来源。来源记录进入题目元数据，面向用户的解析只显示必要的来源名称和链接。

命题质量参考多项选择题研究中的常见缺陷：题干与正确项重复、正确项异常偏长、逻辑或语法提示、明显不可信的干扰项、含糊题干和低认知层级。研究指标用于发现风险，不机械套用医学考试阈值。

## 题库蓝图

每个节点固定 12 道题，分为三个层级：

| 层级 | 数量 | 主要能力 |
| --- | ---: | --- |
| 基础理解 | 3 | 概念、职责、必要条件、适用边界 |
| 应用分析 | 6 | 张量形状、计算过程、错误诊断、方案比较、工程场景 |
| 深度追问 | 3 | 因果解释、跨概念联系、面试口述、连续追问 |

每个节点必须覆盖至少四类认知活动，不能用同一种问法改写 12 次。题型可使用单选、多选、排序和自我回忆；题型服务于能力目标，不为了配额强行使用。

公式只在它是已知条件或推理材料时展示。若公式本身就是待判断内容，则不能同时把完整正确公式放在题干上方。公式题至少要求完成以下一种活动：

- 推导输入或输出形状；
- 判断缩放、归一化或 Mask 的位置；
- 判断参数共享关系；
- 定位错误计算步骤；
- 比较 Self-Attention 与 Cross-Attention；
- 解释数值稳定性、计算复杂度或显存影响。

## 单题编写规范

每道题包含能力目标、题干、选项或参考要点、正确答案、逐项解析、难度层级、知识标签和来源。

题干必须在遮住选项后仍能明确说明问题，且只考察一个主要判断。除必要上下文外不加入无关叙述，不使用模糊的“通常都对”“一定更好”等措辞。

干扰项从以下位置构造：

- 真实概念混淆；
- 正确流程中的错误顺序；
- 合理但不满足当前条件的方案；
- 常见形状、符号或复杂度错误；
- 把相关机制的职责错误交换。

干扰项不得是与题目无关的句子、明显荒谬结论或仅靠绝对词就能排除的表述。正确项与干扰项在长度、语气、信息密度和抽象层次上保持接近。

解析采用“结论 -> 机制 -> 选项差异 -> 边界”结构。多选题逐项解释；计算题给出必要中间步骤；场景题说明为什么其他方案在当前约束下不合适。解析不得引入与正确答案冲突的新结论。

## 审题流水线与职责隔离

题目依次经过“命题 -> 确定性检查 -> 证据审查 -> 命题质量审查 -> 手机人工标注 -> 修改后复审”。命题角色不能批准自己编写的题目，各审查角色不读取命题时的隐藏推理，只读取题目、结构化能力目标、原子事实表和允许使用的来源。

### 命题角色

命题角色根据能力蓝图和一手来源编写题目，同时提交：目标能力、原子事实、正确答案依据、每个干扰项对应的真实误区、适用条件和来源位置。缺少这些材料的题目不得进入审查。

### 证据审题角色

证据审题角色逐项核验题干、正确答案、错误选项和解析，主动寻找第二个合理答案、隐藏条件、版本差异和反例。输出只能是“通过”“修改”或“拒绝”，每个判断必须关联具体原子事实和来源，不能只给整体印象分。

### 命题质量角色

命题质量角色不承担 Transformer 事实核验，专门检查答案泄露、认知深度、干扰项可信度、题干歧义、措辞或长度提示、解析对齐和跨题重复。事实角色与质量角色必须分别给出结论，避免一个整体评分掩盖致命问题。

### Agent 校准

在批量审题前建立 60 道金标准校准集：30 道确认合格题和 30 道人工植入缺陷的题。缺陷覆盖事实错误、多解、隐藏条件、答案泄露、无效干扰项、解析矛盾和表面重复。审题角色在不知道标签的情况下评审，至少达到：致命问题召回率 95%、错误放行率不高于 5%、与人工标签一致率 90%、重复运行结论一致率 90%。未达到阈值时，Agent 只能提供审查意见，不能批准题目。

金标准中的事实标签需要熟悉 Transformer 的人员确认；产品所有者的手机标注用于清晰度、提示、难度和解析价值，不能替代技术事实标签。

## 硬性门槛与锚定评分

知识正确性不使用缺少锚点的连续分数。每道题先通过六项硬门槛：事实正确、答案唯一、条件完整、来源可核验、无答案泄露、解析与答案一致。任一项失败即退回，不允许用其他维度补偿。

通过硬门槛后，再对题目质量进行四项 0–4 分锚定评分：

| 维度 | 0 分 | 2 分 | 4 分 |
| --- | --- | --- | --- |
| 推理深度 | 可抄写或靠形式猜中 | 需要一次有效判断 | 需要多步推理、诊断或权衡 |
| 干扰项质量 | 多数明显无关或荒谬 | 部分来自真实误区 | 全部可信且对应不同真实误区 |
| 题目与解析对齐 | 解析未回答题干或矛盾 | 解释正确项但选项比较不足 | 逐项解释机制、差异与边界 |
| 表达清晰度 | 存在歧义或隐藏条件 | 基本明确但可精简 | 条件完整、语言直接且无形式提示 |

总分至少 13/16，且任一维度不得低于 2 分。1 分和 3 分表示相邻锚点之间的中间状态，审查记录必须说明缺失的具体证据。出现以下任一情况时直接淘汰：

- 页面或题干直接泄露答案；
- 存在事实错误；
- 在给定条件下有多个合理答案但题型未声明多选；
- 正确答案与解析冲突；
- 依赖未说明的实现版本或隐藏假设；
- 缺少可核验来源；
- 与另一道题仅做表面措辞替换。

## 自动质量门禁

新增独立题库质量验证器，在内容验证和持续集成中运行。验证器至少检查：

- 节点数、每节点题数和 3/6/3 层级配额；
- ID 唯一、题型结构和正确答案合法性；
- 题干、顶部公式和正确选项的规范化重复；
- 节点内及跨节点的高重复题目；
- 选项完全重复、异常长度差和明显格式提示；
- 正确答案位置分布；
- 解析是否覆盖正确答案和关键能力点；
- 来源、难度和认知标签是否齐全；
- 禁止使用的弱题干和占位表达。

机器检查负责拦截可确定的结构问题，不能替代内容审查。每道题仍需经过一次事实审查和一次对抗式命题审查。对抗式审查依次尝试：不理解知识点能否靠形式猜中、是否存在第二个合理答案、干扰项是否真的可能被初学者选择、解析能否回答题干提出的问题。

## 手机人工标注模式

手机标注模式只在开发或测试配置下可见，不进入正式版本导航。它复用真实练习卡片和反馈面板，确保标注发生在与用户相同的显示、字号和交互环境中。

标注者先在不看解析的情况下正常作答，再记录作答依据：理解后推理、记得结论、从题面提示看出、排除明显错误后猜测、完全猜测。提交后标注题干清晰度、是否疑似多解、干扰项可信度、答案提示类型、解析是否解决疑问和难度感受，并可填写一条可选问题说明。

每条记录包含题目版本、题目 ID、选择结果、作答时长、上述结构化标签和可选说明。记录默认只保存在本地，可导出 JSON 和 CSV；不自动上传自由文本。修改题目后增加题目版本，旧标注不覆盖，必须重新抽取复核。

产品所有者按每次 10 道完成全部 300 道体验标注。出现答案泄露、疑似多解、多个明显无效干扰项或解析未解决疑问时，该题阻塞进入正式题池。难度感受和单次答错不单独触发淘汰，而用于调整层级和复审排序。

## 分批实施与数据迁移

按现有五个 Section 分批，每批 5 个节点、60 道题：

1. 建立该 Section 的能力目标与来源映射。
2. 重写 60 道题及解析。
3. 运行自动质量门禁和现有课程验证。
4. 完成独立证据审查与命题质量审查。
5. 通过 Agent 审查的 60 道题进入手机全量标注。
6. 修改所有阻塞题并重新经过自动检查、Agent 审查和手机复核。
7. 在 iPhone 尺寸下完成一轮 8 题、一轮 10 题和一轮 12 题会话。
8. 该批次全部通过后再进入下一 Section。

保持节点 ID 不变，避免破坏完成进度。练习 ID 也尽量保持稳定；若题目能力目标完全改变，则使用新练习 ID，防止后续分析把新旧题目误认为同一道题。旧题目不保留在正式抽题池中。

## 上线后质量闭环

匿名分析只记录题目 ID、是否答对、作答时长、所选选项、尝试次数和课程上下文，不采集题目自由文本、简历或个人身份信息。

样本量足够后观察：

- 正确率和分层难度是否一致；
- 作答时长是否异常短或异常长；
- 每个干扰项的选择率；
- 首次作答与重复作答差异；
- 题目与整体表现之间的区分关系；
- 同节点题目是否高度重复测量同一表面记忆。

干扰项长期无人选择、正确率接近全对或全错、区分关系过低、耗时异常或用户集中退出的题目进入复审。由于 Bagu 是自适应学习产品，这些指标只用于预警和排序，不作为自动删除题目的唯一依据。

早期样本使用经典测量指标观察难度、区分度和干扰项效率；样本量和覆盖足够后，离线使用 IRT 估计题目难度与区分参数。自适应抽题、重复练习和样本选择偏差必须保留在分析上下文中，不能把 IRT 输出包装成无条件的题目真值。

## 测试与验收

每个 Section 合入前必须满足：

- 60 道题全部通过六项硬门槛，质量评分至少 13/16 且单项不低于 2；
- 每节点严格为 3 道基础、6 道应用、3 道深挖；
- 所有事实结论有来源，版本敏感结论标明边界；
- 无答案泄露、无重复题、无明显无效干扰项；
- 题干、答案和解析逐题一致；
- 证据审题与命题质量审题记录齐全，Agent 校准达到约定阈值；
- 手机端 60 道题全部完成标注，所有阻塞问题已修改并复核；
- 8/10/12 三种会话均能完成，错题复练、生命值和进度结算正常；
- TypeScript、Lint、Expo Doctor、内容验证、数学公式验证和题库质量验证全部通过；
- iOS、Android、Web 导出不出现新增错误；
- iPhone 移动端检查公式、长选项、反馈面板和按钮无截断或重叠。

全部五批完成后，300 道旧题均退出正式题池，公共课程题目总数仍为 300，课程结构和用户连续进度保持不变。
