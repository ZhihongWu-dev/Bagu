# Bagu 中国大陆匿名体验分析设计

## 背景

Bagu 当前是以本地数据为主的 Expo 应用。课程内容、学习进度、收藏、复习队列、简历文件元信息和项目资料均保存在用户设备上，产品方无法了解真实用户在学习流程中的进入、完成和流失情况。

首批真实用户计划在一个月内通过邀请制 Android APK 参与测试，后续再提交中国大陆 Android 应用市场。首发主体为中国大陆个人开发者，主要用户为 16 岁以上学生和成人。

本设计只解决匿名产品体验分析。可选登录、跨设备学习进度同步、会员权益、简历云存储和公开应用市场发布属于后续独立工作。

## 目标

- 在不要求登录的情况下分析匿名用户的连续学习路径。
- 计算首次体验漏斗、课程完成率、练习难度、流失位置和回访情况。
- 用户拒绝分析时仍可完整离线使用 Bagu。
- 保持 Expo Go 兼容，不因分析功能引入必须使用 development build 的原生统计 SDK。
- 将原始分析数据控制在中国大陆境内，并保持后端提供方可替换。
- 云端、网络和分析代码发生故障时不影响本地学习进度与核心交互。

## 非目标

- 不实现会话录屏、点击热图、广告归因或跨应用追踪。
- 不查看单个匿名用户的完整行为时间线。
- 不上传简历正文、项目描述、自由输入文本或用户选择的答案内容。
- 不在本次工作中实现可选登录或把匿名分析身份绑定到登录账户。
- 不购买或维护传统云服务器。
- 不以首版分析系统替代正式的法律或应用市场合规审核。

## 发布策略

首批测试采用签名 APK 邀请制分发，目标规模为几十名用户。第一份测试 APK 即使用正式且永久的 Android 包名、签名密钥和递增版本号，确保后续应用市场版本可以原地升级并保留本地学习进度。

邀请制测试不免除隐私告知和同意要求。开始向外部测试者上传事件前，必须提供可访问的隐私政策，并根据最终发布范围复核 APP 备案与教育类应用相关要求。

## 技术选型

采用“轻量 TypeScript 分析客户端 + 腾讯云 CloudBase HTTP 接口”的方案：

```text
Bagu 页面和学习流程
        |
        v
统一 Analytics 接口
        |
        v
本地事件队列
        |
        v
CloudBase HTTP 云函数
        |
        v
境内事件数据库 ---> 私有聚合分析后台
```

客户端只依赖标准网络请求和 Expo 支持的本地存储能力，不直接依赖 CloudBase SDK。CloudBase 细节封装在上传适配器之后，未来更换国内分析服务或自有后端时，各页面的事件调用无需改写。

选择该方案的依据：

- Expo 官方说明多数移动分析 SDK 需要自定义原生代码，不能直接在 Expo Go 中运行。
- 友盟 Android SDK 仍在维护，但公开的 React Native 桥接实现分散，未提供明确的 Expo SDK 54 兼容承诺。
- PostHog 提供官方 Expo 示例，但默认云端不是本次中国大陆优先场景的合适数据落点。
- CloudBase 提供中国大陆地域的 HTTP 云函数、数据库和个人版资源，无需购买和维护整台服务器。

参考：

- [Expo Analytics 指南](https://docs.expo.dev/guides/using-analytics/)
- [PostHog Expo 示例](https://github.com/PostHog/support-rn-expo)
- [友盟 SDK 开发者中心](https://devs.umeng.com/)
- [CloudBase HTTP 访问服务](https://cloud.tencent.com/document/product/876/122894)
- [CloudBase 云函数](https://cloud.tencent.com/document/product/876/46899)

## 客户端组件

### ConsentStore

保存 `unknown`、`granted` 或 `denied` 三态同意结果。首次选择前为 `unknown`，分析模块不得初始化、生成匿名身份或发送网络请求。

### Analytics

页面只通过语义化的 `track(event, properties)` 接口记录事件。该模块执行事件白名单、属性白名单、字段长度和数值范围校验。无效事件在开发环境报告，在正式环境静默丢弃。

### EventQueue

分析事件使用独立于学习进度的本地队列。队列最多保存 500 条或 7 天数据，超过限制时删除最旧事件。每累计 20 条、间隔约 30 秒或应用进入后台时尝试批量上传。

### CloudBaseTransport

负责取得匿名安装令牌、批量上传、重试和删除请求。页面与 Analytics 模块不感知 CloudBase URL、认证和响应格式。云端管理密钥不得进入应用安装包。

## 匿名身份与会话

用户同意后，客户端才向后端申请随机安装身份和仅限该身份使用的写入凭证。该身份不来自 IMEI、MAC、广告 ID、手机号或其他永久设备标识。

一次冷启动创建新的 `session_id`。应用卸载后本地身份消失，再次安装视为新匿名用户。可选登录上线后，学习进度可以与账号合并，但匿名分析 ID 默认不与账号身份合并。

每条事件包含服务端生成或校验的身份、唯一 `event_id`、`session_id`、客户端发生时间和服务端接收时间。服务端用 `event_id` 去重。

## 事件目录

### 会话与页面

- `app_opened`：完成本地初始化并进入应用。
- `session_started`：新会话建立。
- `screen_viewed`：进入稳定的可识别页面。

### 课程与练习

- `lesson_started`：进入一节课程。
- `lesson_completed`：满足现有课程完成条件。
- `exercise_answered`：一次有效提交，记录是否正确、尝试次数和耗时。
- `exercise_retried`：错误后再次开始作答。

### 复习与知识库

- `review_added`：条目加入复习队列。
- `review_completed`：完成一次复习操作。
- `knowledge_opened`：打开知识条目。
- `knowledge_favorited`：收藏状态发生改变。

### 功能与设置

- `resume_feature_opened`：进入简历功能，不记录文件信息或内容。
- `project_feature_opened`：进入项目功能，不记录项目资料。
- `sound_toggled`：音效设置改变。

不依赖 `session_ended` 或 `lesson_abandoned` 事件，因为移动应用不保证能在退出时可靠发送。流失位置通过会话最后一个有效聚合事件推断。

## 允许属性

所有事件共享：

- `schema_version`
- `event_id`
- `session_id`
- `occurred_at`
- `app_version`
- `platform`

按事件需要允许：

- 页面、课程、练习、知识点的内部 ID
- 练习类型
- 是否答对
- 尝试次数
- 毫秒级耗时，并设置合理上限
- 收藏或设置改变后的布尔状态

服务端拒绝未列入白名单的额外属性。事件协议使用版本号演进，旧 APK 的合法事件在协议升级后仍可被接受。

## 永久禁止上传的内容

- 姓名、手机号、邮箱、生日、身份证件和登录凭证
- IMEI、MAC、广告 ID及类似永久设备标识
- 精确位置、通讯录、相册和剪贴板内容
- 简历文件名、文件正文、解析结果和项目描述
- 用户自由输入的文本
- 题目正文、答案正文和具体错误选项内容
- 带查询参数的完整外部 URL
- 能够直接识别或合理关联到现实个人的其他字段

服务端可能在基础设施访问日志中短暂处理 IP，但业务事件数据库不保存 IP，也不使用 IP 构造用户身份。CloudBase 访问日志按平台允许的最短实用周期保留。

## 同意与撤回体验

应用面向 16 岁以上学生和成人，不采集生日或身份证明。适用年龄在应用介绍和隐私政策中说明，14 岁以下儿童不属于首版目标用户。

首次启动时分析功能保持关闭。用户看到简短、分层的说明，并获得两个同等可见的选择：

- “同意匿名体验分析”
- “仅离线使用”

选择离线使用后直接进入课程，功能不受限制，也不重复弹窗劝说。设置页提供“匿名体验分析”开关、隐私政策和数据说明入口。

同意后只记录后续行为，不补采同意前事件。用户撤回时立即停止采集、清空本地队列，并发出一次云端删除请求。删除请求是撤回动作所必需的通信，可以在网络恢复后完成；除此之外不再上传分析事件。

同意状态只保存在本机，不作为普通分析事件上传。云端从事件存在与否推断不了用户为什么没有数据，也不得把拒绝分析计为产品漏斗流失。

## 后端接口与校验

CloudBase HTTP 云函数提供最小接口：

- 创建匿名安装身份和受限写入凭证。
- 批量接收事件。
- 删除当前匿名身份的原始事件。
- 为管理员后台提供聚合查询。

上传接口执行以下校验：

- 请求体大小、批次数量和请求频率限制
- 安装凭证和事件所有权校验
- 事件名、属性名、类型、长度与数值范围校验
- `event_id` 幂等去重
- 客户端时间异常检测，同时保留服务端接收时间

异常请求只返回通用错误，不暴露数据库、堆栈、环境变量或其他内部信息。

## 重试与降级

网络失败和 `5xx` 响应采用有上限的指数退避，并加入随机抖动。无效请求和其他确定性 `4xx` 不重试。队列达到上限时丢弃最旧事件，不阻塞用户操作。

分析调用不得成为课程完成、答题、XP、收藏、复习或导航的前置条件。客户端分析错误由模块内部吸收；CloudBase 宕机、超时、数据库限额或凭证失效时，Bagu 的本地功能继续正常运行。

## 数据保留与删除

原始事件最多保留 90 天，并通过数据库过期策略或定时清理任务删除。长期保留的数据只能是无法回溯到单个匿名身份的汇总指标。

撤回分析时删除当前匿名身份的原始事件。删除成功后客户端销毁该身份和凭证。用户重新开启分析时创建新的匿名身份，不恢复此前数据。

## 私有分析后台

后台与 Bagu 客户端分离，仅允许管理员登录并启用 MFA。第一版提供日期范围、应用版本和平台筛选，并展示：

- 每日匿名活跃用户、会话数和平均使用时长
- 打开应用、开始课程、完成练习、完成第一课的首次体验漏斗
- 各课程开始数、完成数和完成率
- 按会话最后有效事件推断的流失位置
- 各练习首次正确率、平均尝试次数和平均作答时间
- 次日和第 7 日回访率
- 知识库、复习、收藏、简历和项目入口的聚合使用次数

后台不提供按匿名 ID 搜索或浏览完整个人轨迹的功能。首测数据量较小时直接聚合原始事件；数据量增长后再引入每日汇总表。

## 安全边界

- 所有传输使用 HTTPS。
- 云端密钥只存在于 CloudBase 环境变量或密钥服务中。
- 客户端凭证只能写入和删除自身匿名事件，不能读取任何用户数据。
- 管理后台与事件写入接口使用不同权限。
- 接口启用限流、结构校验、请求大小限制和幂等处理。
- 生产与开发环境使用独立数据库，测试事件不得进入正式报表。
- 管理员账号使用独立密码、MFA 和最小权限。
- 不在日志中记录事件正文、凭证或禁止字段。

## 测试与验收

### 客户端

1. `unknown` 和 `denied` 状态下不存在分析网络请求，也不生成匿名身份。
2. 拒绝分析后全部学习功能正常。
3. 每个事件只包含协议允许字段，禁止字段在客户端测试中被拒绝。
4. 离线队列、容量限制、7 天过期、批量上传和指数退避符合设计。
5. 重复发送相同 `event_id` 不造成后台重复计数。
6. 撤回后队列清空，不再生成事件，并完成或保留唯一的删除请求。
7. 分析异常不影响答题、课程完成、XP、复习、收藏和页面导航。

### 后端与后台

1. 非法事件、额外字段、超大批次、无效凭证和超频请求被拒绝。
2. 原始数据库不包含 IP、简历、项目正文、自由文本或永久设备标识。
3. 删除接口只删除当前匿名身份的数据，且可安全重复调用。
4. 90 天清理策略可以用缩短时限的测试数据验证。
5. 人工构造的测试会话与后台漏斗、完成率、正确率和回访结果一致。
6. 未登录用户无法访问后台，管理员 MFA 与权限隔离有效。

### 应用验证

1. TypeScript、ESLint、Expo Doctor 和相关自动化测试通过。
2. iPhone Expo Go 与 Android Expo Go 冒烟测试通过。
3. 正式签名 Android APK 在真实设备上完成同意、离线、恢复联网、撤回和删除流程。
4. 通过网络检查确认同意前无分析请求，事件负载不包含禁止字段。

## 一个月首测节奏

### 第 1 周

- 确认并提交本设计。
- 完成腾讯云个人实名认证。
- 创建开发用 CloudBase 环境，并确认地域、计费和日志保留配置。
- 固定 Android 包名、签名和版本策略。

### 第 2 周

- 实现事件协议、同意状态、本地队列和 CloudBase 接收接口。
- 接入最小课程与页面事件。
- 完成客户端和后端自动化测试。

### 第 3 周

- 完成私有聚合后台、数据删除和 90 天清理策略。
- 在开发环境构造会话并核对所有指标。
- 完成隐私政策和测试用户说明。

### 第 4 周

- 生成正式签名 APK。
- 使用少量内部测试设备验证升级、离线、弱网和撤回流程。
- 分批邀请首批测试用户，监控错误率和数据质量。

## 后续演进

首测证明数据有用后，再独立设计游客进度云同步和可选登录。登录系统不得默认获得匿名分析历史，也不得改变用户对分析功能的同意状态。

准备进入中国大陆应用市场前，单独执行发布合规检查，包括应用主体、APP 备案、教育类目判断、隐私政策、SDK 清单、权限清单、安全检测和各市场材料要求。该工作不应通过扩大本设计的分析采集范围来完成。
